# Windows 旧目录迁移保护（2026-11-04）

源码内部版本 `1.7.0+52`，业务 schema 仍为16。本轮推进阶段47的旧库迁移与阶段48的数据保护边界。源码、自动化、包与原生结果分别记录，+51结果保留原归属。

## 行为与边界

- 迁移同时持有目标、源目录的进程租约。并发解析同一目标共用一次迁移；占用或身份不明的目标不再让应用切换到另一份数据库。
- 对回滚日志模式的静止 SQLite 数据库，以 `mode=rw` 禁止创建缺失源库，取得真实 `BEGIN EXCLUSIVE` 后启用 `query_only`，检查完整性。迁移不执行业务写入或 schema 升级，最后回滚并关闭连接；复制前后核对源与副本 SHA-256。
- 只读 SQLite 连接的 `BEGIN EXCLUSIVE` 实际不能排斥另一个读者。专项先捕获该问题，再修正为上述实际独占方式；不能仅凭 SQL 调用成功推断取得写入排他保护。
- 已有WAL／SHM／回滚日志、WAL模式库或正在恢复的源保持原位置，由原位置正常打开／恢复；不对原库执行 checkpoint 或切换日志模式。
- 在目标自己的唯一暂存目录完成文件复制与摘要检查；写入 `location-migration.pending.json` 后发布侧文件，最后发布主数据库作为提交点。主库发布前不允许业务层打开目标。
- 迁移包括通知 epoch、v1日志、存储选择器、增量通知目录及设备窗口偏好。进程锁文件不复制、不删除；历史备份、附件和已完成恢复目录保留原位置，旧目录及原文件不删除。
- 重开时先处理位置迁移意图，再决定数据路径。提交后的目标必须全套摘要一致；未提交时，仅当原位置完整且未改变，才回滚已验证的部分发布。源丢失／改变、目标被改写或不明暂存副本均保留现场并阻止自动初始化，避免选择旧快照或空库。
- 已有目标数据库优先；源／目标原有恢复日志优先于旧候选探测。路径获取失败的备用路径与迁移异常分开处理，迁移异常不再被吞掉后创建另一份数据库。
- 不清扫不明 `.tmp` 文件，不覆盖既有侧文件；不跟随迁移文件或增量目录中的链接。位置迁移最多1 GiB／300个文件，超限保留原位置；增量目录只接纳已知格式的普通文件。遇到格式未知或现场不完整时保留数据，后续人工恢复／旧目录接管仍属阶段48。

# v1.5.1 设备验收

用户可用设备：当前 Mac、iPhone、另一台 Windows 主机、Android 手机。先记录包清单中的提交号与 SHA-256，再记录设备系统版本和实际结果。自动化结果见 [验收台账](Release_Acceptance_v1.5.1.md)，空项表示未执行。

## 安装准备

| 设备 | 候选文件 | 安装与验证边界 |
| --- | --- | --- |
| 当前 Mac | macOS unnotarized ZIP | 解压后首次启动；未公证，不代表正式分发资格 |
| Windows 主机 | Setup EXE / Portable ZIP | Windows 10/11 x64；分别验证安装版与解压版。升级前复制数据库与附件，勿删除旧数据目录 |
| Android | test-signed APK | AAB 不是可直接安装文件。若设备已有签名不同的旧版本，不要为绕过安装错误直接卸载；先备份并确认恢复路径 |
| iPhone | unsigned IPA | 当前仅编译产物，须补充有效 Apple 签名与设备授权后才能安装；不能记为手机安装通过 |

本轮不需要在聊天中提供 API Key、密码、签名私钥或个人数据库内容。缺少真实历史样本时，使用测试账号与脱敏副本，并将结果标为样本测试。

## 四类设备分别执行并记录

1. **首次启动与设置**：确认版本 1.5.1、默认密钥为空；切换中/英/日语言并保存、重启。切换服务商地址后，原服务商密钥不能自动带入新地址。记录界面截图，遮住自行输入的密钥。
2. **录音与回放**：先拒绝麦克风权限，确认不进入假录音状态；再由用户授权，录制一段测试语音并停止、回放。使用真实 AI 识别时需自备可用服务配置，此项与本地录音验收分开。
3. **备份**：创建明确标为测试的任务，保存后在设置点击“备份已保存的数据”。确认成功反馈和两个备份文件；未保存的设置不应误报已备份。附件文件本体不包含在当前备份中。
4. **通知**：创建近期提醒；分别观察应用前台、后台与重启后的提醒；编辑时间、完成、删除后观察旧通知是否仍出现。每个场景记录预期、实测次数和系统权限状态。发现重复、遗漏或取消不一致时记录缺陷，不用“进程启动成功”替代通过。
5. **旧版升级**：仅在保留原始副本后，用真实 v7 脱敏样本升级。比较任务/媒体记录数量和字段、用户自填模型/密钥。历史内置密钥应清除，自填密钥应保留。回退使用旧程序与升级前完整副本；不要直接假定旧程序兼容 v8。

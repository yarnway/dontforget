# 产品文案约定

应用内提示采用简短、专业、直接的表达。以下约定适用于后续界面和功能迭代，中英日三语保持同一含义。

## 表达方式

- 先说明状态，需要用户处理时再给一个明确动作。例：“设置未保存，请检查存储后重试。”
- 成功提示用短语，如“修改已保存”“报告已复制”。不重复“成功”，不用感叹号、宣传语或拟人化表述。
- 按钮用具体动作，如“检查更新”“复制版本”“重试保存”，避免“一键”“开始进行”等冗余前缀。
- 进行中使用“正在同步…”“录音中…”等状态，不夸大为“深度洞察”。
- 空态说明当前没有什么；有必要时补一句入口或下一步，不催促、不责备用户。
- 保留用户操作需要的技术信息，如服务名称、IP、PIN、文件名；隐藏无助于决策的内部架构术语。

## 术语与状态

| 场景 | 用词 |
| --- | --- |
| 普通记录／待办 | 事项 |
| 通知与触发时间 | 提醒 |
| 尚未确认或提交的输入 | 草稿 |
| 本机推理服务 | 本地模型；必要时注明服务名称 |
| 成功保存 | 已保存 |
| 确认未保存 | 未保存，并说明重试动作 |
| 保存结果不确定 | 可能已保存，先核对再重试 |
| 数据已保存、系统提醒失败 | 分别说明已保存和提醒待修复 |

不得把“已提交系统”改写成“已送达”，或把未知构建号、连接失败写成“已是最新”。模型生成计划不等于已创建事项。

## 数据保护提示

精简不能删去会影响决定的信息：覆盖／删除范围、是否可撤销、是否含附件／凭据、加密状态、保全范围和明确确认条件。保持“移除引用”和“删除原文件”的区别。恢复与删除提示不套用普通成功短语。

本轮未改备份恢复、通知诊断等关键保护文案；后续按具体流程单独审阅。字符串键和占位符保持兼容，不用批量替换改变业务含义。

## 提示呈现

无操作按钮的普通成功提示至少显示4秒，调用方指定更长时间时保留该时长；信息、警告与错误至少8秒。带“撤销”等按钮的提示，以及无障碍导航模式下的提示，不自动收起。提示不抢输入焦点或推动页面布局。

源码／自动化、页面渲染与原生读屏验收分开记录，不以缩短字符数代替实际可读性验证。

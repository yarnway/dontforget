## 本轮功能

| 范围 | 结果与入口 | 保留的边界 |
| --- | --- | --- |
| 跨年日历更新 | 普通周期／出门计划的日历设置支持 JSON 文件或粘贴导入，预览地区、各段覆盖和来源后应用。同地区新年度追加，旧年度保留；完全相同的快照重复导入不产生重复数据。可导出当前多年度日历 | 同一覆盖范围修订需明确确认；拒绝只覆盖旧区间一部分的替换，避免默默丢失资料。切换地区须在预览中确认替换。最多4段、合计48 KiB；未知日期不视为已公布工作日 |
| 更新提示 | 检查未来60日逐日覆盖，提示缺失年份，包括覆盖内部的空档；各年度保留独立来源。更新保存时只重排未来未处理日期 | 保留过去、已处理、手动修改、延后、单独删除的日期及暂停状态。没有联网自动下载或认证用户提供的来源 |
| 历史日期管理 | 管理计划的“日期与记录”入口，支持过去／未来／全部、待处理／已处理／已移除、日期范围及标题／日期搜索；分批显示。显示原定日期、当前提醒、事项时间和操作记录 | 完成、跳过、重新打开、移除或恢复只作用于一个日期，操作前显示确认。保留原定时刻和实际操作时间，不自动补造离线期间的完成或错过记录；过去的提醒时刻不重新响铃 |
| 用药历史 | 同一日期入口可检索用药历史及已服用／未服用结果 | 该入口只读；补记、修正实际服药时间继续走既有逐剂核对流程 |
| 清晰采集自动创建周期 | 未配置 AI 时，文字采集可直接识别单一时刻的每天、工作日或单个星期规则；已配置 AI 时，符合现有来源和时间核对条件的文字／图片／语音结果自动生成计划及未来60日独立日期。原文、媒体引用、记录 ID 和创建时间保留 | 学习、情境触发和关联事项沿用各自语义。多时刻、多星期、有限范围、提前关系等无法可靠直接解释的内容保留待核对；无 AI 时先存原文，不擅自安排一次性闹钟 |
| 复杂采集确认 | 确认提案时将已选择的周期、清单及分类与计划／日期在同一事务保存；逻辑任务数量不会被日期数放大 | ID 碰撞或过期代次整笔拒绝。保留原有周期扩展、清单、标签、项目及历史；自动整理不采纳模型虚构的项目／标签 |
| AI 提前建议 | 按日期保存建议锚点，每天拥有对应的建议时刻；采用建议只调整该日提醒，原事项时间、其他日期和计划锚点保持 | 旧独立日期缺少建议参考锚点时保留原始数据，但不显示为可直接采用的建议。修改计划时刻或规则后清除旧建议，避免沿用已失效关系 |

日历资料仍只内置有来源的[中国大陆2026年安排](https://www.gov.cn/zhengce/content/202511/content_7047090.htm)，[北京市政府转载](https://www.beijing.gov.cn/fuwu/bmfw/sy/jrts/202511/t20251104_4258838.html)提供交叉核对。**2027及其他未来年度测试数据为合成夹具**，不作为官方安排发布；用户导入资料的 HTTPS 地址只作为出处保存，不会自动访问，也不等于已认证来源。官方新年度数据的可信获取及更新分发仍为后续任务。

## 数据兼容与回归修正

- SQL schema 16 不变。TaskDetails 继续读取 version 1–4；多年度日历 v2、普通计划 v2 或带日期建议语义标记的独立日期使用 **TaskDetails version 5**。旧客户端会拒绝新格式；降级须使用首次写入 version 5 前的备份，不能直接打开本轮已经更新的数据。
- 单年度日历 v1 和普通计划 v1 继续读取，旧记录不会被自动整体迁移。跨年度覆盖空档保持未知，明确额外日期仍按既有优先级处理。
- 历史操作在同一事务检查计划和日期快照、数据库代次及生命周期；恢复中的旧窗口不可写入。通知失败与业务保存分开反馈，提供“修复提醒”。
- 日期建议按本地日历日与钟点换算，保持跨午夜关系及 DST 下的墙上时刻；跨午夜的工作日采集以事项星期换算提醒星期。
- 全量回归发现确认标题时原有 repeat 元数据被清空，已修正为没有新 repeat 时保留原设置；集成测试继续逐字段核对旧内容，并核对新增确认历史。首次失败日志保留，最终结果只取修正后的冻结快照。
- 更新出门日历保留用户已延后、已移除及已处理日期；暂停计划更新后仍暂停，不重新唤醒已处理事项。

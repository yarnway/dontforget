# 使用场景：有限疗程的多药服用提醒

日期：2026-10-27。状态：首版源码已实现，尚未发布；纳入[第二阶段优先任务](Recording_Reminders_Phases.md#第二阶段长期管理与数据保护进行中)。本页保留完整目标，实际完成范围与待补充部分见阶段台账和下文。

## 场景与目标

用户通过处方截图、药袋或药盒照片、语音、文字记录用药要求，希望一次整理多种药物，按每种药物的数量、服用频率、饭前或饭后要求生成提醒，并在疗程结束时自动停止。

以用户提出的“幽门螺杆菌四联、四种药、分饭前和饭后、约半个月到一个月”为需求输入：先保留为待确认计划，逐药补全处方要求，再生成提醒。四种药不等于四次提醒；同药可以每天多次，不同药也可以出现在同一时段。

“半个月到一个月”是尚未确定的疗程描述，不能自动选成 15 天或 30 天，也不能根据疾病名称自动补齐药物。ACG 对特定优化含铋四联方案说明了明确的 14 天疗程，因此产品不能把用户给出的范围作为所有四联方案的通用默认值；具体药物、剂量和疗程仍按个人处方核对。[ACG 官方指南解读](https://gi.org/journals-publications/ebgi/schoenfeld_sep2024/)

## 需要提取并确认的信息

| 信息 | 目标行为 |
| --- | --- |
| 计划名称与服用人 | 例如“本次用药疗程”；不同服用人的药品与记录分开 |
| 药物名称、规格、剂型 | 保留处方或药袋原文；同名不同规格不得合并，语音近音和图片模糊标为待确认 |
| 每次服用数量与单位 | 分别记录数值与片、粒、袋、mL 等单位；包装总量、药物规格和单次服用量分开 |
| 服用途径 | 原文写明时提取；不把外用等药品推定为口服 |
| 频率与服用时段 | 每天几次、哪些餐次、固定时刻或每隔若干小时分别表达；“每天三次”不直接转换成“每八小时” |
| 与进餐的关系 | 饭前、饭后、随餐、空腹或无要求，保留原文；关系及具体间隔不能互相替换或自动补成某个分钟数 |
| 用餐时间与实际提醒时刻 | 用户确认早餐、午餐、晚餐时间；仅有“饭前／饭后”而没有间隔或明确时刻时，先补充再排程 |
| 疗程起止 | 计划及每种药均可有不同起止日期；显示包含的首末日期及最后一次提醒，避免默认无限重复 |
| 特别说明 | 保留医嘱中原有要求；出现按需服用、递增递减或交替剂量等首版不能表达的规则时，保留记录并提示人工核对，不强行生成固定计划 |
| 字段来源与确认状态 | 关联原图区域、原文或转写片段；区分已识别、缺失、相互冲突和用户已确认；模型置信度不能代替确认 |

药袋说明中的饭前、饭后要求应保留并核对，不能只按方便提醒的时间改写。[NHS 医院药房用药说明](https://www.surreyandsussex.nhs.uk/our-services/pharmacy)

## 主操作流程

1. **采集并保存原件**：复用本地先保存的文字、录音和图片流程；允许多张图片共同补充一份计划，AI 未配置或失败时仍可手工填写。
2. **逐药确认**：展示药品卡片与来源对照；检查药名、规格、每次用量及单位、频率、餐次或时刻、起止日期。不同来源冲突时列出差异，用户选择后再保存；未选中的药品明确列为未纳入，不能静默遗漏。
3. **预览服药时间表**：按日期及餐前／餐后分组，展示首日、常规日和末日的具体时刻、每种药物及用量。用户确认后一次启动；反复点击、重启恢复或迟到模型结果不得重复创建。
4. **查看今日用药**：提供“待服用／已服用／未确认／用户标记未服用”，显示距离下一次提醒及疗程剩余天数；与学习队列及普通待办分别呈现，用药提醒不占学习额度。
5. **处理本次提醒**：逐药记录“已服用”，写入实际时间；“稍后提醒”只改变该次通知，不改变处方时刻、数量或后续间隔。用户记录未服用不等于软件建议跳过。
6. **调整或结束疗程**：修改餐次、医嘱或起止日期时先预览受影响的未来提醒，保留历史实际服药记录。暂停、停用和到期均取消对应未来通知；恢复必须预览剩余计划，不补发历史剂次。

## 排程与记录约束

- 用药提醒默认在确认的服药时刻触发；普通任务的 AI 提前提醒建议不能自动改变服药时间。若额外设置准备提醒，应与实际服药提醒明确区分。
- 餐次时间改变只影响用户确认后的未来剂次；跨午夜时显示具体日期，避免把前一天的晚餐后提醒算入第二天早晨。旅行、时区或夏令时变化若影响已确认的给药间隔，先提示核对，不静默重排。
- 相同餐次可合并通知展示，但每种药、每次服用都有独立身份及状态；不能点掉一条通知就把四种药全部记为已服用。历史通知点击及重复反馈不能影响下一次剂次。
- 疗程日期包含首末日；开始日只安排启动后仍未发生的已确认时段，末日不超出确认范围。每种药独立判断结束；整组计划全部结束后不再生成提醒。
- 漏服或未确认的剂次保留原定时间及状态，展示处方或说明书中的既有指导入口，不自动给出补服、加倍或延长疗程建议。漏服处理需要药品的具体说明。[NHS SPS 漏服指导](https://sps.nhs.uk/articles/advising-on-missed-or-delayed-doses-of-medicines/)
- 已保存计划、系统排程成功、实际送达和用户已服用是四种不同状态。系统失败显示“修复提醒”；专注模式、静音策略和平台后台限制需要明确展示与原生验收，不能承诺必达。
- 用药记录默认留在本机；发送原图或转写给已配置模型时沿用明确的 AI 使用选择。日志不打印完整处方，备份中的健康信息和原始媒体需纳入数据保护设计。

当前可复用[多模态采集](../lib/providers/home_controller.dart)、[AI 确认预览](../lib/ui/widgets/capture_preview_dialog.dart)及[通知修复与排程](../lib/services/notification_service.dart)。[通用周期模型](../lib/models/reminder.dart)已补充间隔、星期与结束范围，首版另增加独立的有限疗程、逐药资料、剂次与确认记录，详见[实现索引](Planning_Implementation.md)。多图联合校对、餐次偏移联动、实际服用时间补录与原生送达仍待完成。

- **2.1 用药计划与手工排程**：建立计划、药品、服用规则和逐次记录；实现起止日期、每日多时段、餐次确认、暂停停用、今日用药和原子保存。同步设计 schema 迁移、历史备份兼容与恢复后的排程重建。
- **2.2 多模态逐药解析**：在手工路径上加入截图／图片、语音、文字结构化提取、字段来源、冲突校对及整组确认。不能直接用通用任务摘要充当药品结构。
- **2.3 通知与服药记录验收**：补齐延后、过期通知、失败修复、疗程期满取消、重启恢复、原生后台送达及数据恢复检查。没有完成本项前不宣称用药提醒闭环已验收。

## 完整验收目标（自动化结果与原生待办分开记录）

| 维度 | 必须核对的行为 |
| --- | --- |
| 多模态 | 四药同图、多图重复、模糊剂量、药名近音、图片与语音冲突均能保留来源；失败无记录丢失或自动启动 |
| 用量 | 区分包装数量、规格和单次用量；缺少单位不通过，用户修正可追溯；不自动换算片数与质量单位 |
| 排程 | 不同频率、餐前餐后、缺少餐次或间隔、首末日、跨午夜均有明确预览；范围疗程与未支持规则不能静默排程 |
| 生命周期 | 单药提前结束、全疗程结束、暂停恢复、修改医嘱只调整未来通知，历史记录不丢；重复保存不生成额外剂次 |
| 单次记录 | 合并展示仍逐药确认；延后不改变医嘱；旧通知、重复点击、并发编辑和数据恢复后的旧回调不会污染新剂次 |
| 数据 | 新旧库迁移与备份预检、恢复、原始媒体关联、健康信息控制和旧版本回退有独立证据 |
| 设备 | 前后台、重启、权限拒绝、专注、断网、跨时区、真实送达、点击定位和停用后旧请求取消分别验收 |

首版已实现本地草稿、文字／图片／录音来源提取、逐药确认、有限剂次、按日记录和暂停／回收站。每药可填写明确时刻及独立日期，留空日期沿用计划日期；饭前饭后要求保留为医嘱说明，尚未自动换算餐次偏移。本轮只使用临时库和替身完成自动化测试，没有配置真实患者提醒，也未验证真实连续疗程送达。

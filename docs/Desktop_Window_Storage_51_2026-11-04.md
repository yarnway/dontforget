# R1：设备窗口偏好独立存储（2026-11-04）

源码版本：`1.7.0+51`，业务 schema 保持 16。此文的源码、自动化、包和实机结果分别记录，不沿用 +50 的原生验收结果。

## 存储与兼容边界

- 窗口尺寸、位置和最大化状态写入受应用进程锁保护的数据库目录内的独立文件 `device-window-preferences.json`，格式版本 1。它是设备状态，不进入 SQLite／JSON 业务备份，也不由业务恢复替换。
- 第一次加载、独立文件尚不存在时，从 `Settings.workspace_drafts_json.windowPreferences` 复制旧偏好；没有旧值时建立默认记录。迁移不改草稿原文，不删除旧窗口条目，不需要 schema 迁移。
- 后续窗口变化只更新独立文件。旧程序降级仍看到迁移前保留的旧窗口位置；升级后以独立文件为准。更高版本格式只回退显示默认窗口，不覆盖其文件。
- 已有本机记录后，恢复另一设备的业务备份不导入其旧窗口位置。备份里的业务草稿按恢复计划导入，旧 `windowPreferences` 键作为兼容数据保留。本机文件缺失时仍按首次迁移规则处理，手工删除该文件会重新触发迁移。
- 损坏的普通 JSON 读取时回退默认值，不复活旧业务库里的窗口位置；下一次有效窗口事件可以修复该文件。超出 4096 字节、目录／链接等不安全路径或未知高版本均保留，不强制覆盖。

## 并发和失败处理

- 同一数据库所有者内序列化迁移、读取和保存，避免迁移覆盖更新的保存。写入采用同目录临时文件、flush、rename 原子替换，失败时不删除旧目标。
- 本地文件 I/O 纳入数据库操作准入和排空：恢复／关闭等待已准入操作，维护开始后拒绝新窗口保存。未完成保存不会在释放进程锁后继续写文件。
- 旧保存结束不回写窗口内存状态，窗口事件保留最新尺寸；关闭时 flush 排在已开始的保存之后。
- 不输出草稿原文或原始异常内容。手机草稿的存储和合并逻辑继续由业务数据库负责。

# 睡眠中到期通知的隔离验收

本流程使用已核验候选、独立沙箱和合成提醒。产品通知提交、真实睡眠区间、系统通知送达、电源设置恢复分别记录，不互相替代。`scripts/sleep_acceptance_policy.py` 只提供观察决策，不直接修改系统设置；本机管理员运行的一次性脚本负责准备和恢复。

## 准备与启动

1. 核对候选进程、数据库版本、启动 UUID、原电源值和原有唤醒计划。以 SQLite backup API 保留一致回退材料。包含真实凭据的材料仅留在私有目录，权限为 0600，不加入 Git 或导出 Settings 内容。
2. 在可保持键盘鼠标空闲的短窗口，由用户在本机终端认证启动经过核验的一次性包装脚本。它先写入独立的 `admin-ready` 标记，等待 arming，此时不改变电源值。进程不存在、启动 UUID 不符或等待过期时重新准备，不重放旧日志。
3. 仅在候选退出时更新隔离合成任务。提醒版本必须读当前值再递增：原生完成任务本身也会递增，不能沿用上一份手工记录。启动真实产品，核对界面、准确时间、稳定 ID、当前版本和 schedule/submitted 哈希链，再写入本轮独立 arming 标记。
4. 包装脚本再次检查目标沙箱、任务、到期时间窗口和原电源值，仅设置属于本轮的绝对唤醒并临时解除禁止睡眠。进入观察后不操作界面；避免额外查询流量干扰睡眠。

## 观察策略

- 读取 `kern.sleeptime` / `kern.waketime` 的秒与微秒，拒绝旧时间对、重复、缺失或倒序数据；只有 `sleep < due < wake` 才证明到期时刻位于真实睡眠区间。
- 提前唤醒后，仅使用与本次内核唤醒秒匹配的 `pmset` Wake/DarkWake 行判定。未知来源、普通唤醒或 `RTP.keyboard` / `UserActivity` 都停止；用户活动不会触发再次强制睡眠。
- 只有明确的提前 DarkWake 可继续：先确认 `SleepDisabled` 仍为 0，再等待 15 秒稳定窗口，下一次请求前再次检查策略。最多六次请求，整体观察受截止时间约束；剩余时间不足时停止。
- 睡眠请求被系统拒绝时停止，不将 `0xe00002e2`（本机 SDK 的 `kIOReturnNotPermitted`）当作可重试的设备忙。读回失败或执行异常保留为失败，不记录成成功。
- 观察返回 0 表示区间覆盖到期；4 表示未覆盖或被活动/策略中断；2 表示执行失败。外层恢复失败以 3 覆盖，最终日志和进程使用同一个退出状态。

无论结果如何，包装脚本恢复原 `SleepDisabled=1`，仅取消本次精确时间及 owner 的绝对唤醒，并独立读回。其他应用的断言、网络设置和唤醒计划保持原有管理方式。相对唤醒写零返回成功与独立硬件读回是两种证据；没有可读属性时仍保留未确认状态。

## 后验与验证

观察结束后读取内核时间、电源日志、专属事件和数据库。系统通知需通过独立 OS 可见结果确认；应用内到期横幅或 schedule/submitted 不等于系统送达。清理合成任务后，再核对 cancel/submitted、数据库完整性和正常退出。完成系统重启还必须核对新的启动 UUID，正常应用重开不足以代替。

支持系统读回的候选可在设置页刷新“系统中的通知”，展开系统保留的标题并核对本轮唯一合成标题。Mac 的读回来自 `UNUserNotificationCenter.getPendingNotificationRequests` 和 `getDeliveredNotifications`，两项分别查询、并非原子快照；未知不能当作零，保留也不代表用户已读。优先在同一候选中完成睡眠前后读回；`--upgrade-from` 只复用 bundle ID 和数据沙箱，ad-hoc 新旧包可能对应不同 OS 通知来源。不能用新包读回为空否定旧来源历史送达，也不能由此确认旧来源已清除。必要时以限定 bundle、请求 ID 和时间区间的 `usernoted` / NotificationCenter 日志补充独立送达与历史记录证据，视觉呈现和用户已读仍分别记录。取得证据后，分别通过原候选清理其合成通知。正常退出后的进程核验使用只读进程信息，避免再次请求原生窗口意外重新启动应用。

策略回归不会改变任何系统电源设置：

```sh
python3 -m unittest discover -s scripts/tests -p test_sleep_acceptance_policy.py -v
python3 -m unittest discover -s scripts/tests -v
```

本机一次性脚本及日志保存在忽略的验收材料目录，具有精确候选/启动身份和已测试策略摘要校验。每次实验使用新的 marker/log；源码更新后不能让未重新核验的旧包装脚本静默加载新策略。

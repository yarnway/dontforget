# 发布与验证策略

更新：2026-10-28，按用户最新要求执行。

- main、手动运行与现有标签继续执行质量检查、五平台构建和产物校验。验证包保留在 GitHub Actions artifacts；不自动创建或发布 RC，也不自动创建 GitHub Release 草稿。
- 工作流只保留 `contents: read`。现有历史 RC 标签及验收证据保留，默认不为每次迭代再创建 RC 标签。
- 以固定源码、版本、清单和摘要识别验证包；发布页面、CI 通过和真机通过分别记录。
- macOS、iOS 所需原生验收及相关回归完成后，再建立对应稳定标签并人工发起正式稳定版发布；发布前核对七包及各平台清单，发布后读回附件、正文与版本。其他平台不要求凑齐真机设备。
- 当前仍有手机通知点击、日文软键盘、真实录音手势与实时活动状态同步待验，不能据构建通过提前发布稳定版。平台签名与分发限制继续在验收总表单独说明。

本轮 `1.7.0+37` / `dfb34f1` 已完成七项 CI；最初草稿在发布前已从远端消失，公开发布未完成。用户调整策略后，停止重建该草稿；仅从对应 CI 恢复并核验产物，没有重新上传或创建 Release。未改变旧的无标签草稿。

参见[发布验收总表](Release_Acceptance_v1.7.md)及[本轮证据](benchmarks/build37-and-native36-2026-10-28.json)。

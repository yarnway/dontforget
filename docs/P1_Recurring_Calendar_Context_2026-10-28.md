## 已实现的行为

| 优先项 | 使用与结果 | 边界 |
| --- | --- | --- |
| 普通周期独立日期 | “计划与清单 → 管理 → 新建／编辑”设置日、工作日、周、月、年重复；新建周期默认勾选按日期独立提醒，旧串行周期可明确转换。生成当前日期起未来 60 日窗口，根计划无闹钟，每个日期具有稳定 ID；漏做、完成、跳过、延后只影响当日 | 旧记录不自动批量迁移。旧周期已逾期、延后或确认的当次必须先处理，防止转换丢失。独立计划通过暂停、回收站或内容归档停止，不直接改回串行 |
| 编辑与恢复 | 在同一事务保存计划及未来安排；只替换未处理的未来日期，保留已完成、已确认、延后、部分勾选、手动编辑、归档、用户删除和逾期日期。暂停后修改再恢复沿用新时刻；撤回日期例外只恢复系统因规则替换的日期 | 用户独立删除的日期不会因为重新补排被复活。启动／维护补齐缺失未来日期，不补造离线期间的服药、完成或错过记录；原生通知继续受共同容量预算约束 |
| 法定节假日 | 默认按原星期／日期；可选避开放假日，或以周一至周五为基础跟随日历工作日和调休。内置有官方来源的中国大陆 2026 安排；出门计划按实际出门日判断，提前到前一天的闹钟保持关联 | 额外明确日期优先于日历，明确跳过优先排除；不越过周期起止。资料未覆盖的日期暂停新增，不擅自把周一至周五当作已公布法定工作日；计划不会被误报期满 |
| 日历导入 | 严格、有界 JSON 日历快照，显示来源、地区与起止覆盖；支持其他已确认地区／年份的离线资料。重复字段／日期、日期溢出、调休冲突、超范围、非 HTTPS 来源及超量输入均拒绝 | 导入替换本计划的日历，非多年度自动合并；确认计划保存前可查看新覆盖。导入来源仅保存为用户资料，不把用户提供的网址当作已核实官方来源，不自动访问该网址 |
| 一次定位与修复 | 天气设置中显式点击“获取一次当前位置”，获取有效点后显示约略坐标，点击采用才写入计划草稿；再沿原计划预览保存。拒绝、永久拒绝、系统服务关闭、平台不支持、过期／无效点均有独立反馈，提供对应系统设置入口 | 不在启动、城市搜索或后台自动定位，不订阅位置流；保存坐标四舍五入至小数点后两位。页面、草稿或维护代次改变后不采用迟到结果；关闭天气后不能采用旧点。权限面板和实际取点的五平台验收另行执行 |
| 天气授权与后台策略 | 默认仅前台；每个计划可单独允许进程仍在运行时的后台天气刷新，只用已确认的保存地点。6 小时内有待提醒日期时最多请求 3 个计划，成功冷却 30 分钟，失败退避 60／120／240／480 分钟；尝试和下次可重试时间持久保存 | 系统可能挂起或终止进程，不能保证退出后刷新，也没有新增后台定位或系统定时唤醒。恢复前台补日期并修正天气；过期或未知天气保留基础清单及“天气待确认” |
| 授权撤回及并发 | 网络等待不占数据库写入／恢复门禁；请求途中退出前台、关闭天气、撤回后台许可、改地点、暂停或恢复数据后，迟到结果不覆盖新状态。内部刷新状态不再使已打开的授权撤回失效 | 不发送出门观察记录或轨迹给天气服务；实际外部服务、系统后台执行和送达效果与离线替身测试分别验收 |

定位使用锁定的 geolocator **14.1.2**。iOS 只声明 `NSLocationWhenInUseUsageDescription`，Android 只增加约略定位权限，macOS 声明定位用途与沙盒位置能力；没有声明后台位置权限。macOS 插件使用其系统支持的授权状态，应用自身仍只在主动操作时采样，不能把它表述为 macOS 系统仅授予前台权限。

## 日历资料与导入格式

内置依据[国务院办公厅 2026 年部分节假日安排通知](https://www.gov.cn/zhengce/content/202511/content_7047090.htm)，并通过[北京市政府转载原文](https://www.beijing.gov.cn/fuwu/bmfw/sy/jrts/202511/t20251104_4258838.html)核对。固定来源、2026-01-01 至 2026-12-31 覆盖、33 个放假日及 6 个调休上班日；未收录的年份保留为缺少资料，不宣称已获得其官方安排。

离线快照严格包含下列 8 项；示例为格式说明，空日期表不代表已核验某年的法定安排：

```json
{"version":1,"id":"region-year-source-date","region":"CN","from":"2026-01-01","to":"2026-12-31","source":"https://example.org/official-notice","holidays":[],"workdays":[]}
```

单份最多 48 KiB，覆盖间隔最多 1095 日，每类最多 366 个严格 `YYYY-MM-DD` 日期。日历随计划与备份保存，不依赖实时远端接口；后续多年度合并、官方更新提示和更便捷的日历文件入口仍独立推进。插件权限能力参照[geolocator 14.1.2 文档](https://pub.dev/packages/geolocator/versions/14.1.2)并检查锁定原生实现。

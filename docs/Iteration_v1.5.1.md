## 本轮实现

1. **配置**：默认密钥为空；删除源码中的可还原凭据；DB v8 使用 SHA-256 指纹只移除旧内置密钥。取消覆盖用户密钥和模型的隐式迁移。保存采用事务，等待初始化，失败不更新状态或关闭页面。切换服务商源时清空旧密钥。
2. **存储**：合并并发打开请求；关闭后释放缓存句柄；打开失败不覆盖原文件。备份读取一致事务数据，创建临时镜像、检查完整性、关闭后替换旧镜像。JSON 快照含全部三张表。设置页提供手动备份和成功/失败反馈。
3. **提醒**：日历计算保留本地墙上时间或 UTC、秒与微秒；月/年循环钳制到有效日期；错过周期跳到未来。明确传入 null 可清除可空字段。解析布尔状态兼容 SQLite 与网络 JSON。
4. **交付**：版本号统一至 1.5.1+2；新增回归测试；widget 测试使用临时数据库；五平台构建依赖质量检查。

## 使用与兼容边界

- 旧源码曾包含凭据。删除源码与本机迁移不能撤销外部服务商凭据；维护者需在对应服务商控制台撤销或轮换，并核查历史发行包。本轮未使用这些凭据，也未改写 Git 历史。
- 设置 → “备份已保存的数据”创建本机 `databases/dont_forget_v3.mirror.db` 和 `databases/ha_snapshot.json`。数据库目录由平台应用数据目录决定。仅备份已保存内容，附件记录保存的是路径，附件文件本体不复制。
- 备份包含 API Key，未加密；两个文件分别完成后替换，不能承诺两者同时切换或覆盖断电的所有情况。失败会返回错误，不能将失败当作成功备份。
- 主库打开失败时停止自动恢复；保留主库与备份供后续诊断。可视化恢复、备份版本管理及启动存储故障提示留待后续版本。
- 月/年循环以当前提醒日期为基准，短月钳制后不保存最初的“31号/闰日”锚点。若要永久保持原始日历意图，需要后续新增锚点字段与迁移。
- 本版未更改 LAN 协议，也未声称加密、冲突安全或跨设备附件同步。

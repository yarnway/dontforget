## 阶段 1：恢复预览

先提供只读的备份检查与预览，暂不替换主库。
支持本项目镜像 SQLite 和带版本的 JSON 快照；拒绝损坏、未知未来版本、
缺表/缺必需字段、重复 ID 和无法解释的字段类型。检查副本，避免触碰源备份。
界面展示时间、版本、三表数量、缺失媒体数量，以及是否包含密钥；
不显示密钥明文，不把路径索引说成附件备份。

验收：v7/v8 合成输入、损坏文件、超限文件、异常结构与缺失附件；
每次检查前后源备份和主库哈希不变。预览可用不等于恢复完成。

### 本轮交付范围

设置页增加“检查备份”，支持中英日、文件选择、取消检查、失败重试和摘要展开。检查器仅复制所选文件到临时目录，在副本上执行 SQLite 完整性/表结构校验或隔离 JSON 校验，不调用主库、保存设置、迁移数据库或安排通知。返回结果仅含版本、时间、计数、附件可访问性、引用问题、密钥存在标记和文件摘要。

- 仅接受 v7/v8 当前可解释的数据格式；v9/未来版本、损坏数据、未知结构、超出 64 MiB/每表 100,000 行、重复 ID/JSON 键和非法日历日期会明确拒绝。旧样本中的对象型子任务或纯文本情境规则不自动转换，也不删除原始数据。
- 普通源文件须为独立快照；检查规范路径及 SQLite WAL/journal/shm，复制前后和结束时复核来源。拒绝用户符号链接；系统路径别名需要核对精确目标。预检不保证抵御恶意并发文件替换，恢复执行仍需重新确认候选内容身份。
- SQLite 预检验证三张业务表的列、类型、约束和外键，拒绝额外可执行结构；兼容经过严格校验的 Android 系统元数据表。旧引擎的表信息查询采用兼容路径，不因平台差异放宽业务 schema。
- 不读取、播放或复制附件内容，不请求网络资源。显示“本机无法确认可访问的附件”，不把沙箱权限不足一律解释为文件丢失。业务表中的文本输入也属于“输入与附件记录”，不误报为纯附件数量。
- 取消后等待校验任务退出和临时副本清理；检查期间不能重复启动。文件路径、密钥、备份正文和底层错误不进入页面错误提示。

Android 元数据来源核对了 [AOSP SQLiteConnection](https://android.googlesource.com/platform/frameworks/base/+/master/core/java/android/database/sqlite/SQLiteConnection.java)；旧表查询兼容依据 [SQLite 3.26.0 变更说明](https://sqlite.org/releaselog/3_26_0.html)。这些源码依据不替代 Android 真机验收。

## 阶段 2：恢复执行与失败回退

暂停数据库写入、自动备份与调度，创建独立回退副本，在临时目录验证并迁移候选库。
主库句柄和 WAL 状态确认关闭后才切换。使用可恢复的操作记录描述切换阶段；
进程中断后必须能判定旧库、新库及回退副本身份，不能凭文件存在猜测成功。
恢复完成后重载设置/媒体/任务，按最终数据库重新建立通知；失败进入明确故障界面，
保留原库、候选和回退材料，不静默覆盖或循环重试。

恢复界面需显示影响、缺失附件、回退位置并由用户确认具体操作。
候选替换不得自动删除历史备份；备份保留策略单独设计。

验收：每个持久化边界故障注入、磁盘/权限失败、并发写入、取消、重启续检；
验证恢复前后数据和通知一致、可回退；先隔离副本，再测试应用包。

### 已实现切片：维护门禁、旧操作隔离与内部恢复引擎

该基础切片保持 schema v8，当时未开放 UI 恢复按钮。以下为该切片的源码与隔离测试进展，不继承阶段 1 候选的构建或真机验收结论：

- `DatabaseHelper` 通过带 `DataGeneration` 的 `read`、`writeTransaction` 和 `runOperation` 提供作用域访问；生产入口不再返回可长期持有的裸句柄。维护开始时同步拒绝新准入并推进代次，排空已接纳的数据库与短操作回调；迟到、过期或故障状态的请求明确失败，不在维护结束后自动重放。
- 提醒/设置/媒体状态、AI 与附件处理、LAN、旧编辑页和 Undo 接入代次隔离。LAN 服务端一次合并及返回快照位于同一事务，客户端只在网络前后使用短数据库作用域；旧响应不能写入恢复后的库，停止服务会排空已接纳处理器。保存、删除与关联变更等待结果，失败不关闭编辑页或显示成功。
- 维护专用关闭不覆盖固定备份。GUI 与 CLI 共用合作式进程所有权及启动预检；预检先处理恢复日志，再校验业务表结构与数据，之后才允许 provider 加载和正常业务入口运行。占用时 CLI 退出码为 `75`，其他启动/恢复错误为 `1`；`--help`/`-h` 不打开数据库，也不执行恢复。
- 内部 `DatabaseRecovery` 重新核对预览摘要，复制并校验 v7/v8 候选，必要迁移至当前 schema；每次操作保留独立目录、原库回退副本、候选及摘要身份。持久化 `recovery.pending.json` 记录切换决定，固定镜像和旁边的 JSON 不作为回退材料。
- 主库关闭且确认无 sidecar 后再替换；本切片仅接受 SQLite 文件头读写格式均为 `1` 的回滚日志格式文件，候选或原库采用 WAL 模式时在写 journal/替换前拒绝，不能把“没有 WAL 文件”当作非 WAL 模式。启动续检根据 journal 的阶段与摘要决定完成已提交切换或回退未提交切换。损坏日志、身份不匹配、回退失败等状态阻断启动并保留材料，不猜测成功、不循环重试。
- 通知维护入口暂停新调度，排空已在途操作并严格取消原生请求；切换或回退后只按最终数据库中的提醒严格重建。取消/重建失败会传播到恢复引擎，保持通知暂停和故障边界；不把原生 API 接受请求当作系统送达证明。
- 通知重建全部成功后才启动进程内计时器，重建期间到期的本轮提醒补发一次；部分原生清理失败必须先重新完成取消，初始化失败允许重试。CLI 退出显式无备份关闭，`--list` 不因此覆盖固定镜像/JSON。
- 候选通知只在 `committed` 决定持久化后启用。提交前失败回退旧库；提交后的通知重建或归档失败保留已提交新库与 journal，保持门禁并在下次启动继续相同决定，不回退可能已发出通知的数据，也不显示恢复成功。

源码验证：静态分析无问题，326 项 Flutter 全量回归和 10 项脚本测试通过。本轮新增 91 项：数据库维护 19、恢复引擎 24、通知维护 7、操作代次 20、LAN 隔离 7、UI 操作隔离 7、启动预检 5、启动故障页面 2。使用临时目录、临时数据库、loopback 伪服务和可控通知实现，覆盖事务排空、跨进程合作锁、旧结果/旧状态拒绝、失败回退、启动续检、WAL 前置拒绝与业务错误保持页面。独立审查发现的 CLI 退出备份副作用、WAL 边界、启动业务校验和通知失败/临界到期问题均已处理。

## 阶段 3：提醒状态闭环

按“任务 ID + 提醒发生时点 + 调度修订”标识一次提醒，区分已计划、已触发、
用户已查看、已延后、已完成及已取消。不能将原生 API 添加成功等同于系统送达，
更不能等同于用户已读。系统缺少送达查询能力时保留未知状态。

持久化确认与延后记录；统一 UI、心跳、循环、情境触发和原生点击的入口，
避免同一次提醒由 Timer、心跳和重启补报重复弹窗。编辑/完成/删除都进入同一调度协议，
原生失败可见且可重试，任务级顺序保护继续保留。

明确专注策略是否跨会话保存；若保存，启动时应先读取策略再重建原生请求。
退出专注后聚合已错过的次要提醒，不批量播放声音。时区、DST、休眠和长期退出后
按用户的日历意图与补偿窗口处理，不能无限补发历史循环。

验收矩阵：前台/后台/退出、授权/拒绝/再授权、编辑/清除/完成/删除、
原生请求在途取消、延后、循环、点击路由、专注/情境、重启、休眠、时区/DST；
每一项均保留数据库状态、原生请求及有界到期观察证据。

## 新增需求：多模型优先级与自动降级

2026-10-21 用户明确要求允许多个模型服务，按可用性和手动顺序使用。本节是完整功能规格，不表示现有候选已经支持多配置。独立分支 `codex/v1.6-model-failover` 的 `9c7a967` 已实现配置值对象和顺序路由基础，10 项专项测试与静态分析通过；原有 86 项加最初 8 项路由测试共 94 项全量通过，随后增加的总超时和并发排序快照两项也通过。当前尚未接入设置界面、持久化、LLMService 或真实服务，因此不能宣称用户可用的多模型功能完成。

- 每个配置独立保存名称、接口地址、模型标识、密钥和启用状态。列表顺序就是用户优先级，提供上移/下移和键盘操作；当前单服务配置无损迁移为第一项。
- 自动降级单独开关，界面说明任务内容可能发送给后续启用服务。关闭时只调用第一项；启用时只在明确配置的列表内切换，禁止替换为未配置的供应商。
- 按顺序尝试可用项；认证/模型配置失败跳过本轮，限流/服务故障进入有期限冷却。冷却到期允许高优先级恢复；可用性只影响本次选择，不擅自改写用户排序。
- 每个请求固定一份配置快照，服务密钥严格对应其地址；切换后不沿用上一服务的 Authorization。未启用、无密钥且需认证、格式错误的配置不发送请求。
- 明确总超时与单次超时，用户取消后不继续降级；不能把接受连接、HTTP 200 或无法解析的内容认定为任务提取成功。全部失败只保存一次本地原文，标明未设置时间；成功后也只创建一次任务。
- 页面安静显示实际使用的配置及降级状态，详细故障放设置页；不显示完整响应、密钥、请求 ID 或堆栈。可用性记录仅保留有限数量且不包含任务正文。
- 配置持久化纳入数据库迁移、备份和恢复预览，标明多份密钥的敏感性。不能另存一个不随备份恢复的隐藏配置文件。

验收：按 A→B→C 顺序、A 恢复优先、手动排序、关闭降级、全部失败、认证/模型错误、429/503、超时/取消、非 JSON、配置并发修改、密钥隔离、无重复任务；先模拟运输层，再使用明确配置的服务做少量原生验证。

## 智能输入、视觉、性能与存储优化

# v1.6 数据恢复与提醒闭环

2026-10-21：本文件为后续实施与验收顺序，不代表功能已经实现。
当前先关闭 v1.5.1 通知候选的发布阻塞；原生包复测结果与源码回归分开记录。

## 阶段 1：恢复预览

先提供只读的备份检查与预览，暂不替换主库。
支持本项目镜像 SQLite 和带版本的 JSON 快照；拒绝损坏、未知未来版本、
缺表/缺必需字段、重复 ID 和无法解释的字段类型。检查副本，避免触碰源备份。
界面展示时间、版本、三表数量、缺失媒体数量，以及是否包含密钥；
不显示密钥明文，不把路径索引说成附件备份。

验收：v7/v8 合成输入、损坏文件、超限文件、异常结构与缺失附件；
每次检查前后源备份和主库哈希不变。预览可用不等于恢复完成。

## 阶段 2：恢复执行与失败回退

暂停数据库写入、自动备份与调度，创建独立回退副本，在临时目录验证并迁移候选库。
主库句柄和 WAL 状态确认关闭后才切换。使用可恢复的操作记录描述切换阶段；
进程中断后必须能判定旧库、新库及回退副本身份，不能凭文件存在猜测成功。
恢复完成后重载设置/媒体/任务，按最终数据库重新建立通知；失败进入明确故障界面，
保留原库、候选和回退材料，不静默覆盖或循环重试。

恢复界面需显示影响、缺失附件、回退位置并由用户确认具体操作。
候选替换不得自动删除历史备份；备份保留策略单独设计。

验收：每个持久化边界故障注入、磁盘/权限失败、并发写入、取消、重启续检；
验证恢复前后数据和通知一致、可回退；先隔离副本，再测试应用包。

## 阶段 3：提醒状态闭环

按“任务 ID + 提醒发生时点 + 调度修订”标识一次提醒，区分已计划、已触发、
用户已查看、已延后、已完成及已取消。不能将原生 API 添加成功等同于系统送达，
更不能等同于用户已读。系统缺少送达查询能力时保留未知状态。

持久化确认与延后记录；统一 UI、心跳、循环、情境触发和原生点击的入口，
避免同一次提醒由 Timer、心跳和重启补报重复弹窗。编辑/完成/删除都进入同一调度协议，
原生失败可见且可重试，任务级顺序保护继续保留。

明确专注策略是否跨会话保存；若保存，启动时应先读取策略再重建原生请求。
退出专注后聚合已错过的次要提醒，不批量播放声音。时区、DST、休眠和长期退出后
按用户的日历意图与补偿窗口处理，不能无限补发历史循环。

验收矩阵：前台/后台/退出、授权/拒绝/再授权、编辑/清除/完成/删除、
原生请求在途取消、延后、循环、点击路由、专注/情境、重启、休眠、时区/DST；
每一项均保留数据库状态、原生请求及有界到期观察证据。

## 阶段 4：界面和多平台交付

恢复入口统一状态文案：检查中、可恢复、需处理、恢复中、成功、失败可回退。
通知状态展示“已安排/未获权限/调度失败/已确认”等真实状态；
不使用无法验证的“保证送达”。保留 375/768/1440 布局和键盘焦点回归。

通过模块回归后提交 GitHub，构建候选；先 Mac 原生复测，再逐台验证
Windows、Android、iOS，明确签名和安装限制。发布草稿只能指向同一批已核验产物。

## 多模型路由基础阶段（独立功能分支）

2026-10-21，`codex/v1.6-model-failover` 添加独立配置值对象与有界顺序路由器。保留用户顺序，支持禁用、自动降级开关、30 秒失败冷却、12 秒单次/30 秒总超时、取消传播，以及进行中配置快照。失败结果仅包含配置 ID 和原因枚举。最多 16 项，健康记录有上限；没有将任务正文写入健康记录。

验证：原有 86 项加最初 8 项路由测试共 94 项通过；随后新增总超时和运行中排序变化两项，路由 10 项全部通过。静态分析无问题。测试使用模拟 transport；尚未对真实模型服务发请求。

边界：这是运输层基础，没有设置界面、数据库迁移、LLMService 接线或真实服务验收，因此当前应用仍只有单配置。下一阶段实现配置持久化/设置排序与明确降级开关，并验证任务只插入一次、备份恢复包含配置。该分支不合入 v1.5.1 发布候选。

## 2026-10-21 多模型配置接入阶段

独立分支现已实现本机配置列表、启停与上下排序、默认关闭的跨模型自动切换开关；设置 v8→v9 增加配置列表和开关，旧单模型配置继续兼容。文字/图片/文件提取接入有界路由，语音转写、报告和微习惯仍使用首个启用配置。更换服务 origin 清除旧密钥，保存前校验配置，页面编辑不发请求。

验证：完整 104 项测试通过、静态分析无问题；其中两项控制器回归，验证自动切换开/关对应实际尝试顺序，所有模型失败只保存一条本地事项、不虚构时间。保存/备份/重开、排序、各模型凭据隔离、无效响应降级及历史 v7→v9 升级均在隔离临时库验证。

# P0 记录与提醒体验

本记录对应隔离工作树中的开发结果，基线为 `bd8f43a`。它不是已发布版本或设备验收结论。

## 本阶段修改

- 本地保存或 AI 多事项保存未完整成功时，保留本次输入的原始文本；可以复制、丢弃或追加恢复到当前输入框，不自动重新提交。部分保存时提示先核对，避免重复创建。失败草稿仅保留在当前应用会话，退出或数据恢复后不会保留。
- 搜索、卡片、应用内提示和 CSV 将基于提醒时间的状态描述为“提醒时间已过”，避免把提前提醒视为事项已经逾期。CSV 的时间列和状态文字同步更名，依赖旧表头的下游工具需要调整。
- AI 提取的提醒时间标记为 AI 建议；用户在详情修改后标记为手动选择。来源无法确认、旧数据迁移以及轮次时间改变但来源不明确时显示未知。当前仍沿用保存后自动安排提醒的流程，尚无保存前确认；来源字段使用 schema 14，历史升级快照、JSON/SQLite 备份检查与恢复均保留旧数据。
- 固定时间按钮改为“下一个 20:00”，使用本地日历计算下一天；详情显示具体日期。
- 详情按需读取保存的提醒轮次、通知日志及系统权限。日志的 `submitted` 仅表示请求已提交，不代表系统展示或送达；缺失、变更或读取失败显示未知。时间、完成状态、分类或重复规则尚未保存时不把旧轮次状态用于新设置。

- Flutter 3.44.9 / Dart 3.12.2：完整 Flutter 测试 **1,254 项通过**；Python 脚本测试 **124 项通过**；`flutter analyze --no-pub` 无问题。
- 新增隔离测试覆盖本地插入失败、并发失败、AI 多事项部分保存、恢复时保留新输入及输入法选词、单条提醒日志与权限状态、分类修改后的状态更新、schema 13 升级及旧 JSON/SQLite 恢复、非法来源拒绝，以及 375 宽双倍字号。
- `TZ=America/Los_Angeles` 下快捷时间日历边界测试通过；这是测试进程中的时间计算，不是原生 DST 通知送达验收。
- 未进行此分支的原生手机、真实通知送达、各平台打包或发布验收。

## 集成与后续阶段

- 同项目另一项并行工作也在修改记录、提醒和 schema 14；其字段包括 `event_time`、`suggested_trigger_time` 和 `workspace_drafts_json`，本工作树的 schema 14 则包含 `trigger_time_origin`。合并前需先只读核对实际数据库和备份是否已有任一版本，再确定迁移编号和按结构识别的兼容方案。若已有两种结构的 schema 14 数据，必须分别识别并升级，不能仅凭版本号判定；同时复核 JSON/SQLite 备份检查、恢复及通知调度。不要直接叠加两份迁移。
- 结合并行方案，补齐独立的事项时间、可持久化草稿及 AI 建议的保存前确认；本分支仅澄清提醒时间的文案，并未新增事项截止时间字段。

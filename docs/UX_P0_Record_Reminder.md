# P0 与 P1 主线集成验收

日期：2026-10-27。本轮源码 `d04a3b0`，已合入本地 `main`，统一使用 **schema 16**。集成 P0 记录／提醒、`1f56958` 的计划与附件备份、`dbebd36` 的实时活动控件修复，并保留 `c841797` 之前各发布和设备记录的原有归属。

## 本轮完成

- **统一两种 v15**：P0 的 v15 带提醒时间来源，任务管理分支的 v15 带 `details_json`。schema 16 保存二者字段并集，按实际结构补齐缺少字段；不凭版本号猜测来源。
- **完整保留扩展数据**：草稿、原文、时间来源、事项截止时间、AI 提案、逐词进度，以及结构化清单、项目、历史和暂停／归档状态均保留。既有记录没有这些数据时保持空值，不补造日期或历史。
- **恢复后的状态保护**：工作台、分类、搜索和统计保留可见性规则；暂停、归档和回收站事项不重新排程或开启实时活动，旧通知链接也不能重新打开相同轮次。无时间的即时情境提醒继续可用，并遵守生命周期状态。
- **AI 确认保留用户元数据**：应用提案时原子保存所选事项；首项保留用户已有清单和项目，不接受 AI 覆盖这些数据。重复确认、预览后并发编辑和旧恢复代次仍拒绝写入。
- **记录草稿与录音整合**：原文先保存，失败副本可查看、复制、丢弃和恢复；输入法组词期间不提交，保存期间继续输入保留两份内容。语音转写失败副本携带显式发送标记，清空后恢复仍需点击发送，回车只换行；追加到现有输入也保留这一规则。
- **macOS 原生构建修复**：为锁定的通知插件补齐 CocoaPods 的 Podfile、锁文件、xcconfig、工程和工作区集成，保留 Swift Package Manager。调试构建及严格签名检查通过。

截止时间与提醒时间独立保存、显示和编辑；延后不移动截止日期。“下一个 20:00”按本地日历计算，搜索的今日／已过筛选按提醒时间。CSV 在原 16 列后追加本地截止时间列。通知状态中的 `submitted` 只表示请求已提交系统。

## 数据库与备份兼容

| 来源 | 处理 |
| --- | --- |
| schema 7–13 | 按历史迁移补齐字段；旧提醒来源保持未知，没有截止时间或扩展信息的记录保持空值。 |
| schema 14：提醒来源 | 完整来源字段结构；保留已有来源，补齐记录、草稿、提案、逐词及扩展字段。 |
| schema 14：记录功能 | 识别基础记录及有无独立提案／逐词进度列的已知完整变体；保留已有内容，补齐来源与扩展字段。 |
| schema 15：P0 记录与提醒 | 包含 `trigger_time_origin`；升级时只补 `details_json`。 |
| schema 15：任务管理 | 包含 `details_json`；升级时只补来源字段，默认未知。 |
| schema 16 | 完整并集；新建库、JSON／SQLite 恢复和备份预检采用相同目标结构。 |

- 升级前创建带来源版本、目标版本与 SHA-256 的只读逻辑快照。未知混合结构、缺列、新增列类型或默认值不符时拒绝升级；事务失败保留旧库版本和内容。
- JSON／SQLite 预检支持 v7–v16，继续检查未知对象、重复 ID、大小、行数、日期及引用。两种 v15 即使没有事项也能恢复；同一 JSON 中混用两种事项结构会拒绝。
- 扩展 JSON 限制字段、长度和嵌套，拒绝重复键、错误版本和无效历史日期；迁移与恢复共用解析规则。诊断不包含原文正文。
- 草稿保存与预检统一为 1,048,576 字符上限；350,001 字符草稿与提案、逐词状态等已有往返用例继续通过。源备份在预检和恢复后逐字节保持。
- 保留独立的 v14、两种 v15 和 v16 固定夹具。旧程序不能直接使用 schema 16，回退需对应旧库或升级前快照。

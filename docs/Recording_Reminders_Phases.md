# 核心功能优化与分阶段验收

日期：2026-10-27。基于 v1.7 工作区推进；本页区分源码、自动化测试与原生设备验收。代码改动不代表公开候选或稳定版已经更新。

## 第一阶段：记录与提醒

### 功能范围

1. **离线快速设时**：输入栏时钟菜单提供晚间 20:00、明早 09:00、自选时间、仅备忘；识别明确的相对时间和中英日日期时刻。无明确时间的内容保存为备忘，不推断截止日期。菜单显示识别或选定的具体日期；晚间选项选择下一次 20:00。键盘和大字体下保持输入栏紧凑。
2. **先保存再整理**：文字先保存原文、本地任务和用户选择的提醒，再在已配置 AI 时后台整理；媒体先导入原件并保存关联记录。服务失败保留记录，可显式继续；重启不会自动发起请求。同一输入草稿携带稳定 ID，避免任务保存后、草稿清除前退出导致重复创建。AI 结果先保存为提案，确认时才以事务应用，期间发生的用户编辑或删除优先。
3. **草稿持久化**：输入文字与时间选择、目标草稿、词汇计划偏好和预览编辑保存在本机。恢复预览保留计划 ID，重新捕获当前数据代次；请求、忙碌状态不会跨重启恢复。配置保存保留草稿列；恢复数据后废弃旧代次的写入。
4. **今天工作区**：今天、未来、全部、分类四种视图，选择自动保存。今天按紧急事项、今日重点、逾期、今日安排、记录与待确认、学习复习组织内容；事项去重，最多三项未完成的今日重点。未指定时间的当日记录与待确认 AI 结果可直接找到。完成或跳过后移出重点；全部以惰性列表展开已完成事项。
5. **事项时间与提醒时间**：分别保存、显示和编辑。AI 提前提醒显示为建议，经用户采用后才改变已保存的提醒。未提供事项时间时不由模型补造时刻；原始记录可查看和复制。今天／未来工作区优先采用事项时间，旧任务沿用提醒时间；搜索的“今日提醒／提醒时间已过／提醒时间优先”只使用提醒时间，避免把截止日期误作提醒。
6. **灵活处理提醒**：保留延后五分钟，增加十五分钟、一小时、晚间、明早、自选时间；周期事项支持跳过本次。延后只改变提醒，不移动事项时间；提醒与事项各自保持周期锚点，避免短月后偏移。关闭提示不等于完成。

### 本轮前移的五项优先优化

| 优先项 | 源码行为 | 操作入口 |
| --- | --- | --- |
| AI 解析确认预览 | 文字、语音、图片、文件、视频解析结果保存为提案；可勾选、修改标题和说明、分别调整事项与提醒时间。暂不应用保留原文，确认后才替换或拆分任务；重复确认和过期回调被拒绝 | 任务卡“确认 AI 解析结果” |
| 今日学习队列与负担控制 | 默认每日总词量 20、新词上限 10，可调整；复习及薄弱词优先，同词去重，额度按当天实际学习记录计算，超额内容保留到之后继续 | 更多功能／今天的学习区“今日学习队列” |
| 单词级掌握度 | “认识／模糊／不认识”只更新当前单词；记录掌握阶段、反馈次数、首学和下次复习日期。同词在现存批次间共享最新反馈，重启和备份保留；同步更新相关批次的复习与提醒时间 | 今日学习队列的逐词反馈 |
| 学习与紧急事项分开排序 | 今天视图分组；全部及未来视图将普通任务、紧急任务与学习条目区别排序。分类视图保留原分类方式 | 今天／全部／未来 |
| 通知失败直达修复 | 已保存但通知同步失败的提示提供“修复提醒”，直接打开权限、排程、系统状态及手动重试。任务完成后卡片消失，失败提示与入口仍保留 | 失败提示“修复提醒” |

学习额度控制应用内队列，不会把超额内容批量标记完成，也不批量改写普通任务的截止时间。词汇记录附属于现存任务；独立词库、删除后长期保留的学习档案和更细的统计仍属于后续阶段。间隔是可解释的默认策略，不代表个人最优记忆曲线。

### 数据与验证

- 集成目标统一为 **schema 16**，沿用三张业务表。保留提醒时间来源、事项时间、AI 建议时间、原文、待整理标记、解析提案、逐词进度、重点标记、事项周期锚点及工作区草稿列。按完整结构识别两类独立 v14、提案／逐词列的已知变体及两类独立 v15；不完整混合结构拒绝升级。固定夹具与具体兼容表见 [P0 集成记录](UX_P0_Record_Reminder.md)。
- 升级前保留带摘要的只读逻辑快照；JSON／SQLite 恢复预检同步支持 v7–v16。旧版本程序不能直接打开 v16，回退必须使用相应旧库与保留的恢复材料。草稿写入与恢复预检统一上限，恢复保留提案、逐词进度和时间来源。
- 所有自动化数据库和通知替身使用独立临时目录，不读写用户数据库或真实系统通知。

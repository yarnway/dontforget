# 增量通知日志原型的验收边界

生产仍使用 v1 原子替换日志。`benchmark/incremental_journal_experiment.dart` 仅用于隔离实验，不由 `lib/` 导入。原型包含稳定 ID 所有权索引、哈希链增量帧与可配置分段检查点；调用方必须独占目录并串行操作，尚不具备生产迁移和多写者租约。

协议 v3 限制单个 manifest 为 4 KiB、检查点为 16 MiB、日志段为 64 MiB、增量帧为 4 MiB。读取前检查文件大小，读取后再次核对；逐帧解析前检查大小，超过帧上限的未结束尾部也拒绝。上限可以缩小进行边界测试，不能扩大超过这些硬上限。目录叶节点、输入文件和写入目标拒绝符号链接；这些检查不替代独占目录或消除并发替换竞态。

超大检查点/帧在写入前拒绝，保持已发布代际及内存状态；日志段容量不足时先检查点轮换，再继续追加。写入中失败会使写者不可继续，需重开建立选定的持久代际。完整损坏帧、校验/链/epoch/ID 所有权不一致均拒绝；只有有界且没有结束换行的最终尾部可以忽略，之后必须先检查点，不能直接追加。

复测使用同一份已关闭的万条合成备份：

```sh
/Users/james/.local/opt/flutter-3.44.9/bin/cache/dart-sdk/bin/dart run scripts/evaluate_incremental_journal.dart --fixture /absolute/path/to/closed/ha_snapshot.json
```

脚本先校验参数，仅在新的临时目录写入；分别比较生产 v1、索引追加、每 24 帧分段检查点。每种模式使用相同 256 条 pending/submitted 批次，分别测首次和已有日志重开，并计入检查点成本。报告包含协议版本、文件/任务行摘要及上限。输出为 JIT 日志组件实验，不是原生前台、产品启动或 OS 调度实测；应重复三个进程，保留全部结果，不能只按写入字节决定上线。

崩溃回归覆盖逐字节尾部截断、完整帧损坏、代际发布边界、稳定 ID 及子进程 SIGKILL。新增上限、容量轮换与链接重定向回归。SIGKILL 不等于断电、目录 fsync 持久性或系统重启。

剩余门禁：生产 v1 迁移/失败回退、跨进程所有权/租约、目录总量上限、选定代际及读者安全的旧代际回收、真实文件系统断电一致性。当前每文件大小有界，旧代际数量仍可能增长；不进行自动删除。

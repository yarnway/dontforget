# 增量通知日志原型的验收边界

生产仍使用 v1 原子替换日志。`benchmark/incremental_journal_experiment.dart` 仅用于隔离实验，不由 `lib/` 导入。原始引擎包含稳定 ID 所有权索引、哈希链增量帧与分段检查点；直接使用时调用方必须独占目录并串行操作。协议 v4 增加 `LeasedIncrementalJournal` 实验适配器，验证迁移、回退、租约和回收，尚未接入产品调度后端。

协议 v3 限制单个 manifest 为 4 KiB、检查点为 16 MiB、日志段为 64 MiB、增量帧为 4 MiB。读取前检查文件大小，读取后再次核对；逐帧解析前检查大小，超过帧上限的未结束尾部也拒绝。上限可以缩小进行边界测试，不能扩大超过这些硬上限。目录叶节点、输入文件和写入目标拒绝符号链接；这些检查不替代独占目录或消除并发替换竞态。

超大检查点/帧在写入前拒绝，保持已发布代际及内存状态；日志段容量不足时拒绝追加，要求调用方先检查点轮换。写入中失败会使写者不可继续，需重开建立选定的持久代际。完整损坏帧、校验/链/epoch/ID 所有权不一致均拒绝；只有有界且没有结束换行的最终尾部可以忽略，之后必须先检查点，不能直接追加。

复测使用同一份已关闭的万条合成备份：

```sh
/Users/james/.local/opt/flutter-3.44.9/bin/cache/dart-sdk/bin/dart run scripts/evaluate_incremental_journal.dart --fixture /absolute/path/to/closed/ha_snapshot.json
```

脚本先校验参数，仅在新的临时目录写入；依次比较生产 v1、索引追加、每 24 帧分段检查点、带租约的分段适配器。每种模式使用相同 256 条 pending/submitted 批次，分别测首次和已有日志重开，并计入周期检查点成本。v4 另记录租约/重放、回收后目录大小、最新状态导出回退及再次迁移耗时；最终检查点或迁移成本单列，不隐含在追加耗时中。输出为 JIT 日志组件实验，不是原生前台、产品启动或 OS 调度实测；重复三个进程并保留全部结果。

崩溃回归覆盖逐字节尾部截断、完整帧损坏、代际发布边界、稳定 ID 及子进程 SIGKILL。新增上限、容量轮换与链接重定向回归。SIGKILL 不等于断电、目录 fsync 持久性或系统重启。

适配器与 DatabaseHelper 共用 `.dontforget.owner.lock` 及同 isolate 的所有权登记，所有读者也持排他租约。存储工作必须集中到一个所有者 isolate，不能从多个 isolate 直接打开同目录；POSIX 文件锁本身按进程而非 isolate 计。先锁定后读取；关闭排空已接收操作，不删除锁文件。SIGKILL 后由 OS 释放锁，不按 PID 猜测或偷锁。它是协作式锁，不能阻止不遵守协议的程序直接写文件。

迁移先保留原 v1 字节，再发布完整增量检查点，最后原子切换 `notification-storage.json`。发布前 v1 仍为权威，发布后只读选中增量状态；损坏时拒绝，不能静默使用旧 v1。回退先写持久意图，将最新增量状态原子导出为 v1，再切换选择器；重开时校验意图、源选择器、旧/新 v1 摘要与最新增量状态后继续完成回退。发现外部修改则保留材料并拒绝覆盖。原始导入副本仍保留。

当前产品仍只实现 v1，但已增加选择器门禁：发现增量或未知选择时拒绝打开陈旧 v1，必须由适配器完成最新状态回退。已发布的更旧二进制不认识该门禁，不能据此宣称任意旧版可安全直接降级。

适配器仅管理 `notification-incremental/`，默认总量上限 256 MiB；未知普通文件计入总量但不删除，链接/非普通文件直接拒绝。写前保留有界余量，容量不足拒绝；每个检查点先固定前一代，再发布新代，持租约回收本命名空间内未被当前/前代固定的 UUID 文件。保留原 v1、当前及前一代。业务数据库、备份及应用其他目录不在回收范围。裸引擎自身不执行代际回收。

剩余门禁：把适配器接入完整产品调度/恢复门禁、明确版本升级与旧版降级路径、多平台文件系统验收，以及真实断电和目录 fsync 持久性。单文件/受管目录有界不等于应用全部存储有界；进程崩溃测试不能替代这些发布验收。

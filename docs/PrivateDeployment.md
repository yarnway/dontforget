# DontForget 3.0 私有化与极客生产力指南

## 🛡️ 数据主权与隐私设计原则
DontForget 在本机保存数据，但远程 AI 请求会发送相关内容给所配置的服务商。数据库和备份尚未实现应用层加密，局域网同步目前为 PIN 校验的明文 HTTP；本机推理需配置本地模型。本指南介绍本地模型部署、局域网同步及 CLI 使用。

---

## 一、端侧大模型本地部署 (Edge AI)

DontForget 支持连接任意兼容 OpenAI 接口规范的本地端侧大模型推理引擎。

### 1. 使用 Docker Compose 一键启动 Ollama
在项目根目录下执行：
```bash
docker compose -f docker/docker-compose.yml up -d
```

### 2. 拉取推荐端侧模型
- **极速小模型 (无显卡 CPU 畅跑)**:
  ```bash
  docker exec -it dontforget-ollama ollama run qwen2.5:1.5b
  # 或
  docker exec -it dontforget-ollama ollama run llama3.2:1b
  ```
- **深度推理思考小模型**:
  ```bash
  docker exec -it dontforget-ollama ollama run deepseek-r1:1.5b
  ```

### 3. 一键端侧探测
打开应用进入 **设置 (Settings) -> 端侧本地模型推理探测**，点击 **“开始探测端侧引擎”**。应用将自动探测 `11434` 端口，点击 **“一键应用到当前配置”** 即可在断网状态下畅享端侧推理！

## 二、去中心化局域网多端同步 (Decentralized LAN Sync)

DontForget 拒绝中心化公共云数据库，采用 **安全 P2P 局域网传输 + 动态 6 位 PIN 鉴权** 模式：

1. **主机开启服务**:
   - 在主设备（如工作台 PC）的设置界面，开启 **“去中心化局域网多端同步”** 开关；
   - 系统将展示本机内网 IP（如 `192.168.1.100:42888`）及一次性动态 6 位配对 PIN（如 `839102`）。
2. **辅机连接配对**:
   - 在同一 Wi-Fi 下的另一台设备（如笔记本或局域网机器）上，输入主机的内网 IP 与 6 位 PIN；
   - 点击 **“开始双向同步”**，两端 SQLite 数据库将在毫秒内完成增量双向合并，无需经过任何公网服务器。

## 三、桌面端极客 CLI 命令行支持

DontForget 桌面端（Windows / macOS / Linux）支持无界面原生命令行静默录入与待办查询。

### 1. 快速录入待办 (`--add` / `-a`)
```bash
# 极速录入，自动分类至重点跟进，并智能设定默认提醒时间
dont_forget.exe --add "明天上午10点评审需求文档并通知研发团队"

# 简写形式
dont_forget.exe -a "下午2点给供应商付款"
```

### 2. 命令行查询待办清单 (`--list` / `-l`)
```bash
dont_forget.exe --list
```
输出示例：
```text
📋 Active Reminders (3):
  • [Q1] 紧急线上Bug修复 (Reminder: 2026-09-10 14:30)
  • [Q2] 明天上午10点评审需求文档并通知研发团队 (Reminder: 2026-09-10 09:45)
  • [Q3] 提交周报 (Reminder: 2026-09-12 18:00)
```

### 3. 命令行帮助 (`--help` / `-h`)
```bash
dont_forget.exe --help
```

`--help`/`-h` 只打印帮助，不打开数据库、不执行恢复。录入和查询共用 GUI 的存储启动预检：先取得进程所有权并检查未完成恢复日志，再检查业务表与数据。其他遵守同一协议的 DontForget 实例占用数据目录时，CLI 明确退出 `75`；请正常退出该实例后重新操作。其他启动或恢复故障退出 `1`，先检查已保存的数据和恢复记录，不要盲目重复写入。

## 四、认知干预与心理学辅助引擎说明

DontForget 3.0 集成了多项认知心理学机制：
- **反“社会懈怠 (Social Loafing)”**：卡片智能感知在重点跟进（Q2）中停滞超 24 小时的任务，提示“🧠 5分钟微习惯拆解”，将庞大任务拆解为极微、无痛启动的行动项；
- **“空船效应 (Empty Boat Effect)”**：当语音或文字输入带有情绪发泄、焦虑词汇时，AI 自动剥离情绪噪音，重构为平和有力的行动清单，并打上 `⛵ 空船效应已重构` 微标，大幅降低心理内耗。


## 五、备份预检与恢复边界（v1.6 分阶段）

设置页“检查备份”先只读检查 v7/v8 JSON 或独立 SQLite 快照，预检通过后可进入单独的恢复确认。检查本身不替换现有数据库，也不表示附件本体已备份、文件在当前沙箱可访问或恢复已完成。确认页显示当前/备份计数、替换影响、附件与凭据提示以及预定回退位置；须勾选知悉后执行。确认期间数据或来源发生变化，会拒绝替换并要求重新检查。

本轮源码加入内部维护与恢复基础：业务访问携带数据代次，维护立即阻止新访问并排空在途操作；旧 AI/LAN 响应、编辑页和 Undo 不能写入新代次。恢复引擎重新确认候选摘要，准备独立候选和 rollback 副本，以 `recovery.pending.json` 记录切换决定；启动时先续检，无法确定文件身份或完成回退时停止进入业务界面并保留材料。固定镜像/JSON 备份不充当该次恢复的回退副本，不应手动删除恢复记录、原库或回退目录来绕过故障页面。

确认执行后，应用暂停通知、LAN 和运行中输入，关闭旧模型请求及本地端口探测，等待本地清理完成再替换数据库。随后按最终数据库严格重建通知和设置/媒体/任务状态，移除旧编辑页、Undo 与草稿，返回新工作台。LAN 不会自动重新监听，需手动开启新会话。取消确认不会暂停这些任务或修改数据；进入恢复后应等待结果，不再提供中途取消。尚无可供用户调用的恢复 CLI。

进程所有权采用合作式锁，只约束遵守协议的新版实例；它不能阻止旧版 DontForget 或其他程序直接读写数据库。故障注入覆盖程序过程边界与重启决策，不是突然断电时目录 fsync 持久性的证明。

内部切换当前只支持无 sidecar、SQLite 文件头读写格式均为 `1` 的回滚日志格式文件；WAL 模式即使已无侧文件也会在替换前拒绝。此限制不改变只读预检的含义。CLI 正常退出采用无备份关闭，查询不会因此刷新固定镜像或 JSON。

提交前失败会尝试回退原库；持久化提交后才启用候选通知，此后的通知重建或归档失败将保留新库与提交日志，阻断正常使用并由下次启动重试。保留提交决定是为了避免通知已发出后又切回旧数据，此状态不显示恢复成功。

恢复结果区分成功、已回退、未应用和需退出重启。无法完成清理、通知重建或 provider 重载时，不继续进入工作台。页面显示操作目录时，不表示其中必然已有可用回退文件；应保留现场材料供检查。

验证记录统一见 [v1.6 迭代记录](Iteration_v1.6.md)。本轮采用隔离真实 SQLite/JSON、应用 widget 和模拟/loopback 环境；真实用户库替换、真机通知取消和重建未验收，录音及播放按用户要求跳过。既有只读预检的 Mac 原生证据不能证明本轮恢复执行已通过原生验收。
